# Migrating to v0.6

This guide covers deprecations and breaking changes when upgrading from godot-rust 0.5 to 0.6.

```admonish warning title="Work in progress"
v0.6 has not been released yet. This page is updated as changes land, so that you can prepare early.
```

```admonish tip title="Smooth transition"
To reduce the friction, we recommend first updating to the latest patch release of the previous minor version, v0.5.6.
Many changes are announced early in the form of deprecation warnings, which contain instructions on how to switch to newer APIs.

You can update your `Cargo.toml` to the latest patch release by running:
~~~bash
cargo update -p godot
~~~
Once you have addressed all deprecation warnings, you can update to the new minor version:
~~~bash
cargo upgrade -p godot
~~~
```

## Entry symbol `godot_rust_init`

The default entry symbol, which Godot calls when loading your library, has been renamed from `gdext_rust_init` to `godot_rust_init`.
Update your `.gdextension` file:

**Before (0.5):**

```ini
[configuration]
entry_symbol = "gdext_rust_init"
```

**After (0.6):**

```ini
[configuration]
entry_symbol = "godot_rust_init"
```

Since v0.5.6, both symbols are exported, and the old one prints a warning when Godot loads the library. In v0.6, only `godot_rust_init`
remains. If you still use the old name, Godot will fail to load your extension.

If you specify a custom name via `#[gdextension(entry_symbol = ...)]`, nothing changes for you.


## Editor placeholders for runtime classes

[#1597], [#1607]: Classes without `#[class(tool)]` do not run in the editor. Godot substitutes _placeholder_ instances for them, which keep
property values but do not execute any Rust code.

In v0.5, creating such an object from Rust code that runs in the editor (e.g. via `new_alloc()` or `new_gd()` inside a tool class or editor
plugin) returns a real instance. In v0.6, Godot's placeholder logic applies here as well, so your `init()`, `ready()` etc. will not run.

v0.5 prints a warning the first time this happens for a class. Run with `RUST_BACKTRACE=1` to see where the object is created.
You have two options:
- If the class is meant to run in the editor, mark it as `#[class(tool)]`.
- Otherwise, enable the Cargo feature `upcoming-editor-placeholders` to get the v0.6 behavior already in v0.5. The feature will be
  removed in v0.6, so remove it again when upgrading.

[#1597]: https://github.com/godot-rust/gdext/pull/1597
[#1607]: https://github.com/godot-rust/gdext/pull/1607


## Shadowing base class members

When a `#[func]`, `#[var]`/`#[export]` or `#[constant]` has the same name as a method, property or constant of a base class, both are
registered with Godot. Which one is used then depends on the static type at the call site, which is rarely what you want.

v0.5 warns about this at startup. In v0.6, it becomes an error. Rename the Rust symbol, or keep it and choose a different Godot name:

```rust
#[godot_api]
impl MyNode {
    // Would shadow Node::get_name().
    #[func(rename = get_display_name)]
    fn get_name(&self) -> GString { ... }
}
```


## `#[base]` attribute

The `#[base]` attribute on `Base<T>` fields has no effect, as base fields are detected by their type. It was still accepted by accident;
v0.5.6 deprecates it, and v0.6 will reject it. Simply remove it:

**Before (0.5):**

```rust
#[derive(GodotClass)]
#[class(init, base=Node)]
struct MyNode {
    #[base]
    base: Base<Node>,
}
```

**After (0.6):**

```rust
#[derive(GodotClass)]
#[class(init, base=Node)]
struct MyNode {
    base: Base<Node>,
}
```


## Removed deprecated symbols

All symbols that were deprecated during the v0.5 cycle will be removed. If you have addressed all deprecation warnings in v0.5.6, you
should be covered. The following table lists the removed symbols and their replacements:

| Removed symbol                                         | Replacement                                                  |
|--------------------------------------------------------|--------------------------------------------------------------|
| Rust getters/setters generated by `#[var]`             | `#[var(pub)]`                                                |
| `vdict!` with `key: value` syntax                      | `vdict!` with `key => value` syntax                          |
| `IObject::get_property()`                              | `IObject::on_get()`                                          |
| `IObject::set_property()`                              | `IObject::on_set()`                                          |
| `IObject::validate_property()`                         | `IObject::on_validate_property()`                            |
| `IObject::get_property_list()`                         | `IObject::on_get_property_list()`                            |
| `IObject::property_get_revert()`                       | `IObject::on_property_get_revert()`                          |
| `Node::duplicate()`, `Node::duplicate_ex()`            | `Gd::duplicate_node()`, `Gd::duplicate_node_ex()`            |
| `Resource::duplicate*()`                               | `Gd::duplicate_resource()`, `Gd::duplicate_resource_ex()`    |
| `Rect2::from_corners()`, `Rect2i::from_corners()`      | `from_position_end()`                                        |
| `Aabb::from_corners()`                                 | `Aabb::from_position_end()`                                  |
| `Aabb::support()`                                      | `Aabb::get_support()`                                        |
| `Rect2::cast_int()`, `Rect2i::cast_float()`            | `Rect2::to_rect2i()`, `Rect2i::to_rect2()`                   |
| `Vector*::cast_int()`, `Vector*i::cast_float()`        | `Vector2::to_vector2i()`, `Vector2i::to_vector2()` etc.      |
| `godot::obj::signal` module                            | `godot::signal`                                              |
| Env vars `GODOT4_BIN`, `GODOT4_GDEXTENSION_JSON`, ...  | `GDRUST_` prefix, see [v0.5 guide][env-vars]                 |

[env-vars]: v0.5.md#environment-variable-renames
